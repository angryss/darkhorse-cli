# Search Indexing Checklist

Use this checklist after publishing a DarkHorse page on the Angry Software Solutions website.

## Website Links

- Create `https://angryss.com/darkhorse`.
- Link from the `angryss.com` homepage to the DarkHorse page.
- Link from the DarkHorse page to the GitHub repository: `https://github.com/angryss/darkhorse-cli`.
- Add the website link back to the GitHub repository metadata and README.

## Google Search Console

- In Google Search Console, use URL Inspection for `https://angryss.com/darkhorse`.
- Request indexing from the URL Inspection result.
- Submit the site sitemap in Google Search Console if one is available.
- Confirm that the page is crawlable, returns a successful status code, and is not blocked by `robots.txt` or a `noindex` directive.

Google Search Console can request indexing through URL Inspection, but indexing is not instant or guaranteed. Expect discovery and indexing to take days to weeks.

Google also supports sitemap submission through Search Console. A sitemap helps Google discover URLs, especially when a new page has few inbound links.

## GitHub Discoverability

- Create the first GitHub release for the public alpha.
- Add a concise repository description that includes `DarkHorse CLI`, `AI-native engineering framework`, and `structured software delivery`.
- Add accurate GitHub topics, such as `ai`, `scaffolding`, `developer-tools`, `openspec`, `workflows`, `dotnet`, `java`, `rust`, and `tauri`.
- Create GitHub Discussions categories or pinned discussions for:
  - Welcome
  - Roadmap
  - Public Alpha Feedback

## Ongoing Checks

- Search Google for `site:angryss.com/darkhorse DarkHorse CLI` after publishing.
- Search GitHub for `DarkHorse CLI`, `AI-native engineering framework`, and `structured software delivery`.
- Keep README, release notes, website copy, and package metadata consistent as the project evolves.
